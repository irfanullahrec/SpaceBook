# Server configuration for speed (compression and caching)

This is an owner step like the ones in `docs/PHASE0_SERVER_STEPS.md`: the repository only holds a **template**, `deploy/spacebook.htaccess`. It is not named `.htaccess`, so it is not active, and the deploy workflow does not upload it, because a wrong `.htaccess` takes the whole site down (HTTP 500 on every page). Nothing in the app depends on it: without it the site works exactly as before, only slower.

## What it does

| Part | Effect |
|---|---|
| `Options -Indexes` | No directory listings (already a Phase 0 step; repeating it is harmless). |
| `mod_deflate` / `mod_brotli` | Compresses HTML, CSS, JavaScript, JSON, SVG. The lazy book files are text, so they shrink 5-8 times. |
| `Cache-Control: no-cache` for html/js/css/json | The browser asks the server every time; unchanged files answer `304 Not Modified` (a few hundred bytes). This is the safe default for anything without a content hash. |
| `Cache-Control: public, max-age=31536000, immutable` for `name?v=<12 hex>` | `lazy.html` (generated by `tools/build/make_lazy.js`) asks for every script, stylesheet and book file as `name?v=<first 12 hex of the sha256 of the file>`. Same bytes give the same URL and never change, so they may be cached for a year; a changed file is a new URL. |
| images and fonts | One week. |

Every directive is inside an `<IfModule>` block, so a module the host does not have is skipped.

## Install (once, after reading it)

1. In cPanel File Manager open `public_html/spacebook/.htaccess` (create it if it does not exist; if it already has lines, keep them).
2. Add the content of `deploy/spacebook.htaccess` (the `Options -Indexes` line may already be there).
3. Reload `https://wantuch.pk/spacebook/` and `https://wantuch.pk/spacebook/lazy.html`. If either shows "500 Internal Server Error", remove the last block you added and tell me which one: the host does not allow that directive in `.htaccess`.

## Check that it works

```bash
curl -sI -H "Accept-Encoding: gzip" https://wantuch.pk/spacebook/js/app.js | grep -i -E "content-encoding|cache-control|content-length"
```

Expect `content-encoding: gzip` (or `br`) and `cache-control: no-cache`. Then ask for a hashed URL (take any `?v=` value from the page source of `lazy.html`):

```bash
curl -sI "https://wantuch.pk/spacebook/js/core/lazy.js?v=<12 hex from lazy.html>" | grep -i cache-control
```

Expect `cache-control: public, max-age=31536000, immutable`.

## Rollback

Delete the lines you added. Browsers that already cached a hashed URL keep it for as long as that URL exists; since the URL changes with the content, nothing stale can be served.

## Not done

Brotli needs `mod_brotli` (many shared hosts only have gzip). Security headers (CSP, `X-Content-Type-Options`, `Referrer-Policy`) are part of Phase 8 and will be added to this template then. The same caching idea (content hashes in URLs) is the basis for the service worker's package cache in Phase 4.
