# Phase 4: offline-first

**Goal.** The app installs on a phone, opens with no connection, and the subjects a student downloaded work completely offline; progress made offline is sent later (the Phase 2 outbox). Nothing is requested from another website while the student reads.

## What exists

| Piece | File | Role |
|---|---|---|
| Web app manifest | `manifest.webmanifest`, `icons/` | Installable on Android Chrome ("Add to Home screen"): name, 192/512 icons, a maskable icon, `start_url` `lazy.html` (changes to `./` at the cut-over). The icons are a drawn planet matching the logo; replace them with the real brand icons whenever you have them (same file names and sizes, `tools/validate.js` checks them). |
| Service worker | `sw.js` + generated `content/sw_version.js` | Three caches: `sb-shell-<version>` (the page and what it needs at start: 103 files, 3.7 MB), `sb-content-v1` (book files, requested as `name?v=<content hash>`, so entries never go stale and are never wiped by an update), `sb-assets-v1` (images, refreshed in the background). Never caches `/api/` or another origin or a non-GET. A new version waits until the student presses "Update now". |
| Offline module | `js/core/offline.js`, `css/offline.css` | Registers the worker, offers the update, and the **"Offline books"** dialog (⬇ button in the header): pick subjects, see sizes and free space, download with progress, verify sha256, remove. Asks the browser for persistent storage. Refuses a download that would not fit, before fetching anything. |
| Offline map | `content/offline_map.json` (generated by `tools/build/make_offline.js`) | For each of the 147 subjects: the book files it loads and the images it shows, found by opening it in a fresh app and rendering every chapter and tab; with sizes and sha256. |
| Offline page | `offline.html` | Shown when a page that is not saved is requested with no network. |
| Read aloud | `js/core/tts.js`, `css/tts.css` | Device voices only (Web Speech). The Google "translate_tts" audio is gone from the English and Urdu readers and from the universal translator. When the device has no voice for a language its read-aloud buttons are hidden (`<html class="sb-no-voice-ur">`); voices load late, so nothing is hidden until the first list arrives or 2.5 s have passed. Boundary events highlight the word spoken; voices that send none get a timed walk through the words. |
| Fonts | not bundled yet | The `fonts.googleapis.com` link is removed (it asked for "Segoe UI", which Google does not serve). Urdu/Pashto/Arabic use the device's fonts, as before. See "Waiting for you". |

## How it is switched on

The lazy page (`lazy.html`, and `index.html` after the cut-over) starts everything: the button, the badge, the service worker (on https or localhost). The normal `index.html` does nothing unless `localStorage.sb_offline = 'on'`. After the cut-over change `start_url` in the manifest to `./`.

Offline use needs the shell installed once: open the lazy page while online, wait for the first screen, then download the subjects wanted from the ⬇ dialog. A book that is not on the device and not reachable raises `sb:lazy-error`; the page shows "This subject is not on the device" instead of a blank screen, and the file can be fetched again later (a failed load no longer leaves the file marked as loaded).

## Tests (all in CI)

- `node tests/offline/sw.js` (33): install caches the whole shell and takes over at once; an update waits for `SKIP_WAITING`; activate deletes only old shells (content and asset caches survive); a failed install leaves no half cache; routing (POST, API, other origin untouched); hashed files cache-first; shell files with no network; offline navigation falls back to the entry page; unhashed images answered from cache and refreshed; a full disk still answers.
- `node tests/offline/offline.js` (41): estimate counts shared files once; download stores files under the hash URL and records the subject; a tampered file is refused (integrity), a host that serves CRLF still verifies; quota before and during a download; no network; abort; removing a subject keeps files another subject shares; the dialog end to end (open, select, size on the button, progress, done, remove, Escape); the update banner; the offline badge; the lazy-error message.
- `node tests/offline/tts.js` (23): voice lookup and gender hints, buttons hidden per language, English and Urdu readers speak through `speechSynthesis` with no Audio element and no request, a cancelled utterance does not skip a sentence, no `translate_tts` left in the scripts.
- `node tests/offline/mutate.js`: 9 deliberate breakages (no shell cleanup after a failed install, update that takes over by itself, activate that wipes the content cache, API cached, cross-origin cached, shell not served from the shell, integrity check removed, shared files deleted, quota check removed): every one must make a test fail (all do).
- `node tools/validate.js` (offline section): manifest and icons valid, the shell and every book file and image of the map exist, the manifest starts the page the worker precaches, no third-party request at start-up, no cloud speech.
- `node tools/build/all.js --check` also covers the offline map and the worker version (a changed script changes both).

## Measured

All 147 subjects in the offline map; subject sizes range from 0 (pre-school pages, always available) to 28 MB (Class 10 Physics). The app shell is 3.7 MB (about 1 MB compressed). Sizes of what a subject needs are real (opened in the app and rendered completely); the biggest are Class 9/10/12 Physics (26-28 MB, one 18 MB book + 7 MB patched Class 9/10 data), Class 12 Chemistry (20 MB), Class 12 Economics (18 MB).

## Found on the way

- Rendering a Class 9/10 Physics chapter loaded the 18 MB Class 12 Physics book just to ask "is this chapter one of its chapters?" (`PHYS_12_DATA.includes(ch)`, 6 places): now only asked on Class 12. Class 6-10 subjects whose key is shared with Class 11 (urdu, hpe, civics, isl) loaded the Class 11 book through `class11BookByKey`: now only for Class 11. The English 10 reader asked `DATA.eng10Chapters.includes(ch)` for Class 11/12 chapters: the cheap flag is checked first. Rendered output is unchanged (9,710 renders compared).
- **Not fixed:** `cls6_book_reader.js` `ensureBookReady` merges the *Class 6* book's word list into every other class's book of the same subject, so opening a Class 7-10 English, Urdu, Islamiat, Science, Quran, Arabic, Computer, Drawing, HPE or Pashto subject loads the whole Class 6 book (1-4 MB) for its words. That is a data coupling that belongs to the lexicon work (Phase 7); until then those subjects download their Class 6 sibling too (the offline map includes it, so offline is correct, only larger).

## Not verified (honest list)

Everything here ran in Node (fake Cache Storage, scripted network, jsdom) or was checked statically; **no real browser was available** (Chrome could not run for lack of memory; the in-app browser refused to open localhost). So not seen: service worker registration and update on a real device, the install prompt and "Add to Home screen", a synchronous XHR answered by a service worker (it should work: the lazy loader's XHR is same-origin and controlled), real Cache Storage quota behaviour (the 7-day eviction of Safari without persistent storage is the known risk on iPhones), Lighthouse PWA audit, the look of the dialog and banner, speech on real voices (boundary events differ between engines), push of the outbox after reconnecting (covered by the Phase 2 tests in Node).

## 2026-10-24: writes made offline

A signed-in student's coins and steps, study plans and test records used to be lost when the call failed. `js/core/offline_queue.js` now keeps such a call in a small queue (localStorage), answers `{ok:false, queued:true}` (the page counts the step locally at once) and sends the queue when the browser is online, when the page is shown again, a few seconds after load and every minute. The newest save of a plan replaces older ones; a call the server answered (even with an error) is never queued; each item carries the student's id and is sent only in that student's session. `tests/sync/offline_queue.js`. The Android app's page (a WebView) uses the same script; its native events use the Room outbox and WorkManager as before. The books themselves work offline in the browser through the service worker and in the app through its own copy (`SiteStore`, now encrypted: `docs/PHASE8_SECURITY.md`).
