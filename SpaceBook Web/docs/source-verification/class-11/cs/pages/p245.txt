## 7.5 RELATIONAL SCHEMA || ۷.۵ ریلیشنل اسکیما || ۷.۵ اړونده طرحه
p A relational database schema is the tables, columns and relationships that make up a relational database. The schema describes how real world entities are modeled in the database. An ER Model is intended as description of real world entities but it represents the conceptual level of the database design and must be translated into a logical level of database design. || ریلیشنل ڈیٹا بیس اسکیما وہ ٹیبلز، کالم اور تعلقات ہیں جو ریلیشنل ڈیٹا بیس بناتے ہیں۔ اسکیما بیان کرتا ہے کہ حقیقی دنیا کی انٹیٹیز کو ڈیٹا بیس میں کیسے ماڈل کیا جاتا ہے۔ ای آر ماڈل کا مقصد حقیقی دنیا کی انٹیٹیز کی وضاحت ہے لیکن یہ ڈیٹا بیس ڈیزائن کی تصوراتی سطح کی نمائندگی کرتا ہے اور اسے ڈیٹا بیس ڈیزائن کی منطقی سطح میں ترجمہ کرنا ضروری ہے۔ || د اړوند ډېټابېس طرحه هغه جدولونه، ستونونه او اړیکې دي چې اړوند ډېټابېس جوړوي. طرحه بیانوي چې د ریښتینې نړۍ وجودونه په ډېټابېس کې څنګه ماډل کېږي. د ER ماډل موخه د ریښتینې نړۍ د وجودونو تشریح ده خو دا د ډېټابېس ډیزاین مفهومي کچه ښيي او باید د ډېټابېس ډیزاین منطقي کچې ته وژباړل شي.
p A relational database schema helps users to organize and understand the structure of a database. This is particularly useful when designing a new database, modifying an existing database to support more functionality, or building integration between databases. || ریلیشنل ڈیٹا بیس اسکیما صارفین کو ڈیٹا بیس کی ساخت منظم کرنے اور سمجھنے میں مدد دیتا ہے۔ یہ خاص طور پر اس وقت مفید ہے جب نیا ڈیٹا بیس ڈیزائن کیا جا رہا ہو، زیادہ فعلیت کی حمایت کے لیے موجودہ ڈیٹا بیس میں ترمیم کی جا رہی ہو یا ڈیٹا بیسز کے درمیان انضمام بنایا جا رہا ہو۔ || د اړوند ډېټابېس طرحه کاروونکو سره مرسته کوي چې د ډېټابېس جوړښت منظم او ځان ورته پوه کړي. دا په ځانګړې توګه هغه وخت ګټور دی کله چې نوی ډېټابېس ډیزاین کېږي، د ډیرو فعالیتونو ملاتړ لپاره موجود ډېټابېس تعدیلېږي، یا د ډېټابېسونو ترمنځ ادغام جوړېږي.
## 7.5.1 Transformation of E-R Model into Relational Schema || ۷.۵.۱ ای-آر ماڈل کی ریلیشنل اسکیما میں تبدیلی || ۷.۵.۱ د E-R ماډل اړوندې طرحې ته بدلول
## a. Transforming Entities to Relational Schema || الف۔ انٹیٹیز کی ریلیشنل اسکیما میں تبدیلی || الف. وجودونه اړوندې طرحې ته بدلول
p Each entity set is replaced by a table or a relation. Each table has a name. The name used is the entity name. Each table has a number of rows and columns. Each row corresponds to an entity instance. Each column corresponds to an attribute. || ہر انٹیٹی سیٹ کو ٹیبل یا ریلیشن سے بدل دیا جاتا ہے۔ ہر ٹیبل کا ایک نام ہوتا ہے۔ استعمال ہونے والا نام انٹیٹی کا نام ہوتا ہے۔ ہر ٹیبل میں قطاروں اور کالموں کی ایک تعداد ہوتی ہے۔ ہر قطار ایک انٹیٹی انسٹینس کے مطابق ہوتی ہے۔ ہر کالم ایک ایٹریبیوٹ کے مطابق ہوتا ہے۔ || د وجود هره ټولګه د جدول یا اړیکې په واسطه بدلېږي. هر جدول یو نوم لري. کارېدونکی نوم د وجود نوم دی. هر جدول یو شمېر قطارونه او ستونونه لري. هر قطار د وجود له یوې بېلګې سره سمون لري. هر ستون له یوه خاصیت سره سمون لري.
## b. Transforming Attributes to Relational Schema || ب۔ ایٹریبیوٹس کی ریلیشنل اسکیما میں تبدیلی || ب. خاصیتونه اړوندې طرحې ته بدلول
p Each attribute of the entity type is replaced by a column (field) in the table. Suppose we have an Entity Type Student that has attributes, SID, Name, Major and GPA. All the attributes of Student entity will become columns in the Student table. Figure 7.18 shows this transformation. || انٹیٹی ٹائپ کے ہر ایٹریبیوٹ کو ٹیبل میں ایک کالم (فیلڈ) سے بدل دیا جاتا ہے۔ فرض کریں ہمارے پاس انٹیٹی ٹائپ اسٹوڈنٹ ہے جس کے ایٹریبیوٹس ایس آئی ڈی، نام، میجر اور جی پی اے ہیں۔ اسٹوڈنٹ انٹیٹی کے تمام ایٹریبیوٹس اسٹوڈنٹ ٹیبل کے کالم بن جائیں گے۔ شکل ۷.۱۸ یہ تبدیلی دکھاتی ہے۔ || د وجود د ډول هر خاصیت په جدول کې د ستون (ساحې) په واسطه بدلېږي. فرض کړئ چې موږ د زده کوونکي وجود ډول لرو چې خاصیتونه یې SID، نوم، Major او GPA دي. د زده کوونکي د وجود ټول خاصیتونه به د زده کوونکي جدول ستونونه شي. ۷.۱۸ انځور دا بدلون ښيي.
