# Visual Reasoning Engine: implementation plan (draft, 2026-10-20)

Status: **only the Class 12 Maths Unit 2, Ex 2.1 Q3(a) prototype exists** (`js/q_anim_comp3a.js`). Nothing else is converted. This file is the plan for the controlled batches in the master directive; it is not a completion report.

## 1. What the prototype gives us
Reusable (to be lifted into `js/vr/engine.js`): the step state machine (one index, `go()`, run-id cancellation), SVG overlay + measured coordinates, `arrow()` (curved, animated), `fly()` (chip along the same Bézier, timer-driven so it works in hidden panes), `tip()`, `underline()`, KaTeX `\htmlClass` tagging, sticky nav, speed selector, reduced-motion path, scoped CSS (`.sbt`).
Question-specific (stays in data): the six step bodies, the explanations, the tagged tex.

## 2. Pipeline
`verified solution (existing steps/solution/answer, authoritative)` → `structured steps (this schema)` → `teaching plan (confusion check → animation kind)` → `renderer (engine)` → `student interaction (Guided / Quick / Full / Practice)`.
The animation never computes the answer. A step may only carry a `move` if `from` and `to` tags exist in its `before`/`after` tex; the validator rejects it otherwise.

## 3. Step schema (additive; old fields untouched, so old content keeps working)
```
vr: { v:1, steps:[{
  id, kind,            // substitute | combine | expand | exponent | cancel | balance | factor | formula | convert | check ...
  before, after,       // tex with \htmlClass{id}{...} tags (stable ids)
  moves:[{from,to,label}], marks:[{id,role}],   // role: source|target|op|result|error
  rule, why, mistake?, // short text; mistake = common error to warn about
  domain?, units?, verify?, aria
}], answer }
```
Items without `vr` are never converted silently; `tools/vr/audit.js` lists them as "needs review".

## 4. Batches (each ends with a checkpoint + browser check)
1. **Engine extraction**: move the prototype's helpers into `js/vr/engine.js`, keep Q3(a) working identically.
2. **Algebra kinds**: substitute, combine, expand, exponent, cancel (with domain), balance. Convert Ex 2.1 Q3(b)-(d), Q4.
3. **One more Maths chapter** (Unit 3 differentiation: chain/product/quotient).
4. Physics numericals (formula mapping, unit conversion), Chemistry (atom-count balancing, moles), Statistics, CS (binary/Boolean).
5. Practice Mode, Quick/Full modes, dark theme tokens.
6. Coverage report (`docs/09_VR_COVERAGE.md`) generated by the audit tool; offline + performance measurements.

## 5. Rules carried forward
- No global CSS; everything under `.sbt` / `.vr-*`.
- Typesetter safety: no `^`, `_`, `\(` or letter+digit text in widget text nodes; KaTeX `output:'html'`.
- Generated files: after adding a script, run `node tools/build/all.js --only lazy,search,offline` (about 5 min). The app's real entry is `lazy.html`, not `index.html`.
- Source errors are reported, never silently corrected.

## Status 2026-10-21: the arithmetic narrator and the accumulating board

Reported by the owner (Class 6 Maths Unit 3, Exercises, `{ ( \overline{10 1/3 - 2/9 / 5/16} ) x 1/4 + 1/4 }`): the animated board had FEWER steps than the plain solution beside it (5 steps of three lines, against 6 steps with typeset fractions and a sentence each), and it blanked a line after two steps instead of using the board. Cause: the data rows that start with `=` have no chain, so the old splitter read the English sentence ("2/9 / 5/16 = 32/45") and merged chain-less steps.

**`js/vr_arith.js`** (new, pure functions, also runs under node)
- `SBVR.arithSpec(steps)`: parses the question and every book row (exact rationals: whole numbers, decimals, fractions, mixed numbers, negatives, small powers, ( ) [ ] { } and the bar), checks that all rows have the same value, re-does each operation in small steps and returns a spec whose final value must equal the book's. Mixed number to improper fraction, LCD and "multiply the top and the bottom", flip and multiply for division, multiply numerators and denominators, reduce, then write the result back; negatives settle the sign first ("different signs: subtract the smaller from the larger, the answer takes the sign of the larger"); decimals: same decimal places or take the decimal points out and put them back; powers as repeated multiplication. Brackets that hold one number are removed as their own step. The book's sentence is shown beside the matching step only when the book's next row is exactly the line reached.
- Safe by construction: every line of work is parsed back and must have the value of its operation; a step that changes the value, a non-terminating decimal, a number over 1e9 or anything unparsed makes it return null and the older presentation is kept.
- `SBVR.bookRowsSpec(steps)`: for any other solution whose rows all carry TeX and continue the line above with `=`: the book's own rows, shown verbatim, two steps per row (pick out the part that changes with the book's sentence, then replace it and write the new line).
- Result on the books' data: Classes 5-8 and 11, 111 solutions narrated (book 388 steps -> 1,369 board steps, x3.5) and 14 by the rows narrator; the rest have no TeX rows (word problems) and keep the older presentation.

**Engine** (`js/vr_engine.js`, spec flag `acc`)
- Accumulating board: every line stays (the older boards erase a row two steps later). Lines of one piece of work form a group that never splits across columns; groups that are finished dim to 72% and brighten on hover.
- Layout planner (`planAcc`): measured once on a hidden copy holding all lines; picks the largest text size (1.0 down to 0.62) and the fewest columns (1 to 3) that hold EVERY line in the board's height; the rest of a column goes to the top of the next one, with a dashed line between; a short solution gets a short board; on a phone one column; if nothing fits the board scrolls. Re-planned when the full-screen board opens or the window changes.
- Dark theme, reduced motion and Practice mode are unchanged; non-`acc` specs go through the same code paths as before (`validate_specs.js`: 4,431 specs, 0 errors).

**Checks**
- `node tools/vr/validate_arith.js [--fuzz 3000]`: KaTeX renders every row, tagged variant and `$...$` in an explanation; every op targets a row and a `.k-tag` that exist; final row is the last state; each board has more steps than the book list. `--fuzz` makes random questions (fractions, mixed numbers, decimals, negatives, powers, every bracket) and requires every line of work to be true.
- `tools/vr/view_arith.html?n=6&id=s470&step=29&dark=1` shows one solution on the board in the browser.
