# Baselines

- `html-YYYY-MM-DD/` — **HTML snapshot** (`node --max-old-space-size=8192 tools/snapshot_html.js`): for every class x subject x chapter x tab, tab labels in order and a hash of the rendered tab HTML. No browser needed, ~2 min. It follows the three real views (the generic reader, the Maths view, and the 12 pre-school pages without chapters, captured once as `landing`), blanks the content element before every tab, starts every render from the sub-selection values `state` had at load (the app leaves the last question category, lesson sub-tab and exercise number in `state` for the next subject: finding ARCH-02), and normalises the ids that vary per render (sb_mcq ids, the random part of Maths diagram ids, the class prefix of shared-book answer ids). With that, subjects rendered forward and in reverse order give identical hashes. `html-2026-10-19` was replaced: it hashed stale content for the five Maths subjects and lacked the landing pages. Compare two runs with `node tools/snapshot_html.js --compare <dirA> <dirB>`; a refactor is accepted only if every difference is listed and intended. Does not see layout, fonts or what add-on scripts do to the live DOM.
- `run.js` — **Playwright baseline** (DOM text hashes, console errors, timings, screenshots at 1280x800 and 375x812). Needs about 1.5 GB of free RAM per page; not yet run to completion (see docs/PROGRESS_LOG.md).
